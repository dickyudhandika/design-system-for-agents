# ds4a Vision — the living design system loop

Status: **shipped in v2.2.0** (2026-11-17); command surface simplified to
`init`, `diff`, `tone`, and `apply` in v2.3.0. This document is the record of the
loop the library now runs: detect → preview → build → codify. Every phase below
is implemented; the non-goals still hold. Open questions that were resolved are
marked with the decision; the rest stay open.

## The loop

```
init ──► detect an existing system (or seed the neutral baseline)
   │
   ▼
preview ──► renders the project's actual system (tokens + specimens), not just contracts
   │
   ▼
build ──► the agent (or the human) builds with the system
   │
   ▼
detect ──► /ds4a diff spots components the system doesn't cover yet
   │
   ▼
codify ──► approve → contract in the library → appears in the preview
   └──────────────────────────────────────────► back to build
```

One input feeds everything: `library/core.md` + `library/tones/<tone>.md` +
`<project>/.ds4a/project.md`. DESIGN.md and preview.html are **two render targets
of the same layers**, never sources of truth themselves.

## Principles (unchanged)

1. **The layers are the truth; artifacts are views.** No hand-edited DESIGN.md,
   never a hand-edited preview. If a human wants to change something, they
   change the overlay; the artifacts regenerate.
2. **Never overwrite files the user owns.** Generated files carry the
   "Generated by ds4a" marker; everything else is read-only to the tool.
3. **Detect, then ask — never silently replace.** Ambiguity (doc vs code,
   two sources of truth) gets surfaced with both values, and the user decides.
4. **Grow by promotion.** Project → tone → core, gated on usage
   (`library/usage.md`), never by taste in the moment.
5. **The loop is per-project and opt-in.** The library stays project-agnostic;
   divergence lives only in overlays.

## Phase 1 — one truth per project (shipped)

- [x] Overlay tokens detected from the project win over the tone; gaps fall
      back to neutral.
- [x] Overlay can subtract, not just add: `exclude_components`, `<!-- replace -->`
      sections. (2026-11, resolve.py v2.1.0)
- [x] Hand-written `DESIGN.md` exists → init stops and asks (keep both / adopt /
      abort); doc-vs-code drift is reported, not silently resolved.
- [x] **Blend recipe**: migrate a hand-written DESIGN.md into the overlay
      (verified against code), then regenerate DESIGN.md in place.
      (`scripts/blend.py`, 2026-11; extracts doc frontmatter + tables, compares
      against CSS/DTCG/typed tokens, prints conflicts with both sources, keeps
      unique prose as project notes, `--adopt` backs up and replaces the doc.)
- [x] **Adopt-mode flag**: `resolve.py --adopt` (and `blend.py --adopt`) after a
      confirmed adopt, so the single-file end-state is one command.

## Phase 2 — the preview shows the project, not just the contracts

`build-preview.py` renders the 13 contracts painted with project tokens, and now
also renders *your* Pill, *your* bookmark card: the catalog of *this project's*
system.

- [x] **Overlay-declared specimens.** A `.ds4a/specimens/` directory of raw
      HTML/CSS snippets (`pill.html`, `bookmark-card.html`, …), captured from
      the real component markup, rendered in the preview under a "Project
      specimens" section above the core contracts. (`scripts/specimens.py`.)
- [x] Specimen header records provenance: source file, capture date. Specimens
      are copies, not iframes of the dev server — the preview stays a static
      file with zero build integration. Drift is flagged when the source is
      newer or missing.
- [x] Contracts the project excluded (overlay) are hidden from the preview
      (already true) and replaced by its specimens where one exists (a specimen
      may declare `contract: <Name>`; the Contracts matrix reports it).
- [x] `diff`'s specimen pass (scripts remain): candidate detection — files under
      `src/components/` (and astro/react/svelte equivalents) with no matching
      specimen or contract — presented as an add/skip list.

## Phase 3 — `/ds4a diff` closes the loop into the preview

The specimen/coverage scan finds "code uses something DESIGN.md doesn't define"
and "this component has no specimen". Phase 3 makes that detection productive:

- [x] Diff finding class with a one-command fix: `add-specimen` →
      `specimens.py add <slug> --from <file>` writes
      `.ds4a/specimens/<name>.html` from the component's markup, registers it in
      the overlay, rebuilds the preview.
- [x] `diff`'s merge step gains target `preview`: a merged rule can ship with a specimen,
      so "approved into the design system" literally means "renders on the page".
- [x] Net effect: shipping a new component with `/ds4a` costs one approval and
      appears in the preview — the loop closes with zero ceremony.

## Phase 4 — `/ds4a apply`: tokens into the code, automatically

The agent still reads DESIGN.md when it builds, and ds4a can now write the one
file it owns, so values can be imported instead of hand-copied.

- [x] `/ds4a apply` generates `src/styles/ds4a-tokens.css` (or a Tailwind
      `@theme` block, flag-selected) from the resolved overlay. One new file,
      never edits existing files, prints the one import line to add.
      (`scripts/apply.py`.)
- [x] `/ds4a apply --check` reports drift: overlay says X, token file says Y,
      and lists hardcoded hex/px in `src/` that match a token (migration
      candidates). Writes nothing.
- [x] Explicit non-goals for v1: no rewriting of component files, no codemods,
      no touching `tailwind.config` in place. `@import` line is the human's.

## Phase 5 — the preview as the design system's front door

- [x] Static, self-contained, shareable (host it at `/design` if the project
      wants): a Foundations group (type/color/spacing/radius/elevation with
      real swatches), Components (project specimens + core contracts),
      Contracts (matrix status: enforced / excluded / grown / specimen),
      Tokens (resolved values, copy-on-click).
- [x] This is the "single source of truth" experienced by humans — but the
      source remains the layers; the page is always `resolve.py && build-preview.py`
      away.
- [x] Anything hand-edited in it is lost on rebuild, by design; edits go to the
      overlay.

## Non-goals

- **Not a Storybook.** No prop knobs, no controls panel, no per-variant story
  files. Specimens are static renderings; interactivity demos (hover lifts,
  focus rings) are CSS.
- **No auto-refactoring.** Tokens get generated; components get detected and
  offered, never silently rewritten.
- **No cloud/service.** Everything stays local files in the repo, diffable in
  git like any other change.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Specimens drift from real components | Provenance header (source path + date); `diff` flags specimen/source drift as a warning |
| Preview becomes hand-edited and rots | Generated banner + all edits flow through overlay; build-preview overwrites wholesale |
| Two truths re-emerge (overlay vs specimen copy) | Specimens hold markup/CSS only — *values* always come from the same tokens; drift shows up visually, not silently |
| `apply` writes into the wrong place | Emits exactly one new file; refuses to run if it exists and lacks the marker |
| Scope creep into component codegen | Explicitly out; specimens are copied, not generated |

## Open questions

1. Specimen format: **decided** — `.html` fragments with inline `<style>`,
   referencing token custom properties only. Simple, robust, tone-switchable;
   no dependency on the project's built CSS.
2. Should `diff` auto-run on a git pre-commit hook, or stay explicit?
   **Decided:** explicit; hooks are the user's to add.
3. Does `apply` target CSS-first (`ds4a-tokens.css`) only, or also emit a DTCG
   `tokens.json` for projects already on a typed registry? **v1 is CSS-first**
   (plain `:root` or one Tailwind `@theme` block). DTCG export is still open.
4. Promotion on the preview: should promoted-to-core components get a badge in
   the catalog (project → tone → core provenance)? **Partly:** the Contracts
   matrix reports `Grown`; full provenance badges are still open.
