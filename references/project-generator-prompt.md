# Project DESIGN.md generation

`DESIGN.md` is **built by `scripts/resolve.py`**, not hand-extracted. This file
documents what the script does so an agent without Python can reproduce it, and
holds the project-type taxonomy.

```bash
python3 <skill>/scripts/resolve.py --project .            # tone/type from .ds4a/project.md
python3 <skill>/scripts/resolve.py --project . --type landing-page --tone warm-sharp
python3 <skill>/scripts/resolve.py --project . --check    # report only
```

## What it does

1. Merge tokens: `library/core.md` → `library/tones/<tone>.md` → `.ds4a/project.md`
   (later wins; overlay comments are dropped). YAML values may reference other
   tokens with `{{rounded.md}}`, so changing one scale step cascades.
2. Fill `{{path}}` placeholders in prose from the merged tokens.
3. Assemble sections in canonical order (Overview, Colors, Typography, Layout,
   Elevation & Depth, Shapes, Components, Do's and Don'ts, Pre-flight
   Checklist). Tone content reads first in token-heavy sections, core first in
   Components / Do's and Don'ts / Pre-flight. Overlay prose is appended
   (an overlay `## Overview` replaces the tone's).
4. If a project type is set, drop component contracts and layout lines the
   matrix (`references/component-matrix.md`) marks ❌ for it. Unknown
   `(grown)` contracts are always kept.
5. Write `DESIGN.md` with a "Generated by ds4a resolve" header. It refuses to
   overwrite a `DESIGN.md` without that header (use `--out`/`--force`).
6. Warn on: contrast failures (`muted-foreground`, `foreground`, button text),
   matrix components lacking a contract, unresolved placeholders (fatal).

Always included regardless of type: full frontmatter, Overview, Colors,
Typography, Shapes, Do's and Don'ts, Pre-flight Checklist. The old 30–50 % size
target is gone — it was not achievable with all tokens and guardrails kept.
The report prints the actual size.

## Project types

| Type | Description | Key components | Layout pattern |
|---|---|---|---|
| **dashboard** | Analytics, admin panels, data-heavy screens | Card, Badge, Button, Input, Select, Table | Sidebar + grid + stat cards + data table |
| **landing-page** | Marketing, product showcase | Button, Card | Hero + feature sections + CTA + footer |
| **auth-flow** | Login, signup, password reset, onboarding | Input, Button, Card, Field, Form | Centered card, single column |
| **settings** | Preferences, account config | Input, Select, Button, Field, Fieldset | Section-based forms, save bar |
| **data-table** | CRUD lists, inventory, user management | Table, Badge, Button, Input, Select | Filter bar + table + pagination + modal |
| **content-site** | Blog, docs, knowledge base | Card, Badge | Header + content column + footer |
| **e-commerce** | Catalog, cart, checkout | Card, Badge, Button, Input, Select, Field | Product grid + detail + cart + checkout |
| **admin-panel** | Internal tools, CMS | Card, Badge, Button, Input, Select, Table, Field | Sidebar + top bar + content + modals |

The component and layout matrices and the keyword → type table are in
`references/component-matrix.md` (single source; the script parses it).

If the request doesn't match, use the closest type and say so.
When a project needs a component the matrix drops (landing page with a signup
form), add the type's missing contracts by choosing the closer type, or set no
`type:` to include everything.

## Quality checks (after generating)

- [ ] All frontmatter tokens present; every `{{…}}` resolved
- [ ] Guardrails and checklist present
- [ ] Only relevant contracts for the type
- [ ] No rules invented — everything comes from core, the tone, or the overlay
- [ ] Self-contained: a developer can drop `DESIGN.md` into the repo and the
      agent needs nothing else
